# Security policy

## What to report

Use this policy for vulnerabilities in:

- the document generator or validation scripts;
- repository automation or dependency configuration;
- generated PDFs, including unexpected active content, embedded files, scripts, unsafe actions, or sensitive metadata; and
- a repository process that could expose credentials, personal data, diagnostic evidence, or release integrity.

Windows configuration questions, product-support requests, disagreements with a recommendation, and ordinary documentation errors are not security vulnerabilities in this repository. Use the appropriate GitHub issue form for those reports.

## How to report privately

Submit a report through [GitHub private vulnerability reporting](https://github.com/Amyashi/amys-security-baseline-controls/security/advisories/new).

Include:

- the affected release, file, or commit;
- a concise description of the impact;
- safe reproduction steps;
- any proposed mitigation; and
- only the minimum redacted evidence needed to understand the report.

Do not open a public issue for an unpatched vulnerability. Do not submit credentials, recovery keys, access tokens, full logs, memory dumps, device identifiers, account data, public IP addresses, or other sensitive evidence.

## Supported versions

Only the latest published release is supported. Drafts, forks, modified copies, and untagged build artifacts are not supported releases.

## Response and disclosure

Reports are reviewed on a best-effort basis. Receipt is not a promise of a particular response time, fix, reward, or coordinated-disclosure schedule. Please allow reasonable time to investigate and prepare a release before public disclosure.

Security advisories and corrected artifacts will be published through GitHub when appropriate.
